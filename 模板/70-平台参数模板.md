# 8. 平台参数模板

这里放不同平台的参数写法。
注意：OpenAI 的 Images API 参数和 Midjourney / SDXL 参数不是一套东西，不要混写。

## 8.1 OpenAI gpt-image-2 写实竖图

严格 9:16 手机竖图优先用接近 9:16、且边长为 16 的倍数的自定义尺寸：

```text
model: gpt-image-2
prompt: 使用自然语言分段提示词
size: 1024x1824
quality: medium
output_format: jpeg
output_compression: 85
background: opaque
```

适合：README 预览图、写实 cosplay、竖图人像、漫展手机随手拍。

### 尺寸建议

| 档位 | size | quality | 用途 |
| --- | --- | --- | --- |
| 草稿手机图 | `640x1136` | `low` | 先看角色锚点、防串和构图 |
| 快速严格 9:16 | `720x1280` | `low` | 快速试画面方向 |
| 常规预览 | `864x1536` | `medium` | README 预览和普通角色图 |
| 仓库默认 | `1024x1824` | `medium` | 写实漫展手机随手拍主力档 |
| 细节预览 | `1088x1936` | `high` | 角色卡、封面、海报预览 |
| 高细节交付 | `1440x2560` | `high` | 已确认不串角色后再用 |
| 最大实验 | `2160x3840` | `high` | 最后放大用，成本高 |

本仓库用这个命令校验内置尺寸档位：

```powershell
python 工具/validate_gpt_image2_parameters.py --check
```

临时检查单个尺寸：

```powershell
python 工具/validate_gpt_image2_parameters.py --size 1024x1824 --require-9-16
```

使用规则：

- 如果目标是手机竖屏展示，提示词里继续写「9:16 竖图，vertical portrait composition」。
- `1024x1536` 是 2:3，不要把它当成严格 9:16；只有工具不支持自定义尺寸时才作为备选。
- 如果工具限制尺寸，优先遵守工具返回的可用档位，不要把不可用尺寸硬塞进参数。
- 先用低/中质量确认角色锚点、防串和构图，再提升尺寸或质量。

### 质量档位建议

```text
quality: low       # 快速草稿，看构图、防串和大色块
quality: medium    # 常规成图，适合 README 预览和普通角色图
quality: high      # 海报、角色卡、信息图、电商拆解等细节密集图
```

不要一开始就全部用 high。先用 low / medium 看角色有没有串，再把稳定提示词升到 high。

### 输出格式建议

```text
README预览图：jpeg 或 webp
需要无损细节：png
需要控制体积：jpeg/webp + output_compression
写实漫展/街拍：background: opaque
```

写实照片类默认用 `background: opaque`。透明背景、输入保真度等能力以当前 OpenAI API 校验为准；如果工具不支持，提示词里硬写「透明背景」不一定稳定。对 `gpt-image-2` 编辑任务，优先用提示词写清「保留 / 修改 / 不要修改」，不要依赖不适用字段。

## 8.2 OpenAI gpt-image-2 提示词写法

优先用分段自然语言，把「不可变角色锚点」放在最前面：

```text
任务模式：生成一张 9:16 竖图写实手机照片。
不可变主体锚点：{角色专属提示词}
必须保留：{发型、头饰、服装体系、关键道具、气质}
场景环境：角色站在室内漫展展位旁，背景有人群和灯牌但轻微虚化。
镜头构图：普通观众视角，手持手机随手拍，主体半身清晰。
光线材质：展馆自然顶灯，真实布料、刺绣、金属扣、宝石和发丝质感。
文字策略：不需要文字，不要水印、logo、乱码。
安全约束：端庄自然，非低俗，不性感化，不插画风，不 CG 渲染。
防串约束：不要混入其他角色发型、帽子、服装配色、道具和气质。
```

少用这类空泛堆词：

```text
masterpiece, best quality, ultra detailed, 8k, beautiful, perfect face
```

## 8.3 OpenAI gpt-image-2 图像编辑

```text
model: gpt-image-2
image: 输入参考图
prompt: 明确写保留什么、修改什么、不要修改什么
```

编辑类提示词模板：

```text
保留：人物身份、脸部特征、发型、头饰、服装配色、关键配件、姿势和镜头角度。
修改：只把{错误部分}改成{正确部分}，或只把背景改成{新场景}。
不要修改：不要换角色，不要换发型，不要换服装体系，不要低俗化，不要生成乱码文字。
```

## 8.4 OpenAI 参数避坑

```text
不要写进 OpenAI API 参数：--ar 9:16、--style raw、--stylize 50
不要把 negative prompt 当作单独字段硬塞，除非当前工具明确支持
不要用真实品牌 logo、真实平台水印或长段小字测试模型文字能力
```

如果只是把提示词复制到网页工具，而不是直接调 API，就把参数写在提示词开头：

```text
目标规格：9:16 竖图，接近 1024x1824，写实手机照片，公开展示安全。
```

## 8.5 Midjourney 竖图写实

```text
--ar 9:16 --style raw --stylize 50
```

适合：想要更听提示词、更少自动艺术化。
如果画面太普通，可以把 `--stylize 50` 改到 `--stylize 100` 或 `--stylize 150`。

## 8.6 Midjourney 半身头像

```text
--ar 3:4 --style raw --stylize 75
```

适合：头像、半身、重点看发型和头饰。

## 8.7 Midjourney 全身图

```text
--ar 9:16 --style raw --stylize 50
```

并在正向词里加：

```text
full body, head to toe visible, shoes visible, complete outfit
```

## 8.8 SDXL / WebUI 通用比例

```text
832x1216 或 768x1344，竖图，CFG 5-7，采样步数 25-35
```

适合：写实角色 cosplay 图。
如果脸太 AI，降低过度画质词，增加「手机随手拍、真实皮肤纹理、不过度磨皮」。

## 8.9 Flux / 自然语言模型

```text
用完整自然句描述，不要只堆关键词。重点写清楚：角色是谁、站在哪里、谁在拍、光线怎样、服装材质怎样、不要什么。
```

Flux 一类模型通常更适合自然语言描述，所以可以少用括号权重，多用清楚句子。
