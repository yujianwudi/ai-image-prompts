# 仓库质量门禁

这个文件记录本仓库后续持续优化时必须守住的检查项。
目的：模板越加越多，也不能变乱、断链接、丢安全约束。

## 本地检查命令

优先运行统一质量门禁：

```powershell
python 工具/run_quality_gate.py
```

如果修改了 Prompt Pack 配置并需要刷新自动导出文件：

```powershell
python 工具/run_quality_gate.py --refresh-generated
```

底层命令如下：

```powershell
python 工具/build_prompt_pack.py --validate
python 工具/audit_character_prompts.py --check
python 工具/lint_prompt_quality.py --check
python 工具/validate_failure_fix_lexicon.py --check
python 工具/validate_output_evaluations.py --check
python 工具/summarize_output_evaluations.py --check
python 工具/suggest_failure_fixes.py --check
python 工具/build_project_dashboard.py --check
python 工具/validate_gpt_image2_parameters.py --check
python 工具/sync_preview_manifest.py --check
python 工具/check_prompt_repo.py
python -m compileall -q 工具 tests
python -m unittest discover -s tests -v
```

检查内容：

- 必要目录是否存在：角色、模板、示例、评估、参考仓库、工具、配置、生成提示词、预览图、tests。
- 必要文件是否存在：AGENTS、README、角色索引、模板索引、角色防串审计报告、Prompt 文本质量审计报告、失败修正词库、预览图 README、预览图 manifest、预览图 manifest schema、参考仓库追踪、核心模板文件、配置文件、测试文件、统一质量门禁、GitHub Actions、GitHub 协作模板和仓库格式配置。
- Markdown 是否为空、疑似编码损坏或存在未闭合代码块。
- `.gitattributes` / `.editorconfig` / `.gitignore` 是否保留 UTF-8、LF、二进制图片规则和本地噪音忽略规则。
- 实际文本文件是否无 CRLF、无 UTF-8 BOM，并保留末尾换行。
- 文本文件中是否出现常见 API key、GitHub token、AWS key 或高风险明文 secret。
- README 和文档中的本地链接、图片引用是否存在。
- README 徽章数量是否与 Prompt Pack、角色和模板文件数量一致。
- 内容安全政策是否保留非低俗、不性感化、不儿童化、隐私和真实品牌 logo 约束。
- 授权与使用边界是否保留第三方 IP、官方授权、预览图、商用和正式 LICENSE 提醒。
- AGENTS 是否保留自动化维护者需要的质量门禁、刷新生成文件、gpt-image-2 参数、内容安全、LICENSE 边界和密钥提交禁令。
- 角色文件是否保留“非低俗 / 不性感化 / 不要混入”的安全与防串约束。
- Prompt Pack 输出是否保留主体锁定、安全约束、防串约束。
- 角色防串审计报告是否与当前 Prompt Pack 配置同步。
- Prompt 文本质量审计报告是否与当前 Prompt Pack 配置和 `评估/prompt_quality_rules.json` 同步。
- Prompt 文本是否满足结构、安全、质量、模板意图、角色识别点、长度范围和禁用词预检规则，避免把 Midjourney / Stable Diffusion / LoRA 等外部平台参数混入 `gpt-image-2` Prompt Pack。
- 失败修正词库 JSON 是否结构有效，是否无未知字段、空白文本和重复 applies_to / detect_terms / must_include，`评估/失败修正词库.md` 是否与 JSON 同步。
- 结构化出图评分示例是否符合 `评估/output_evaluations.schema.json`，评分记录 ID 是否为小写 slug，是否混入未知字段，评分日期是否是真实日历日期，评分总分、Prompt Pack、角色、图片路径是否存在且为 jpg/jpeg/png/webp，version / description / issues / next_action / notes 是否包含非空白字符，failure_ids 是否有效且不重复。
- `工具/new_output_evaluation.py` 是否能生成带 Prompt Pack、角色、图片路径和去重 failure_ids 的评分记录骨架，并在输出前复用结构校验拦截非图片路径。
- 出图评分汇总是否与结构化评分记录同步。
- 失败修正建议是否与结构化评分记录和失败修正词库同步，且只对 `edit` / `regenerate` / `reject` 记录输出待修提示。
- 项目仪表盘是否与 Prompt Pack、标签、预览图、失败规则和评分记录同步。
- gpt-image-2 推荐尺寸档位是否符合当前模板记录的尺寸约束，并且 `1024x1536` 没有被误标成严格 9:16。
- Prompt Pack 模板 `api_profile` 是否包含 `model=gpt-image-2`、合规 9:16 `size`、合法 `quality` / `output_format` / `background`，且 jpeg/webp 压缩率规则正确。
- GitHub Actions 是否使用 Node 24 运行时对应的 `actions/checkout@v6`、`actions/setup-python@v6`，并设置 `contents: read` 最小权限与 10 分钟超时。
- 参考仓库追踪清单是否包含三个外部 awesome-gpt-image-2 仓库。
- 预览图是否存在，是否过大。
- 预览图是否全部登记到 `预览图/manifest.json`，schema 是否存在，尺寸/比例/方向是否与实际图片一致，manifest 和 README 是否无重复预览图，README 引用是否都在 manifest 中，预览图 `alt`、展示 caption 和展示顺序是否与 manifest 一致，且 `public_safe=true`。
- `工具/sync_preview_manifest.py --check` 是否确认预览图尺寸元数据未过期。
- Prompt Pack 配置是否可读取、可校验、无断引用，角色/模板/Pack ID 是否只使用小写字母、数字和下划线。
- Prompt Pack 配置是否绑定 `$schema`，schema 文件是否存在且结构完整，并对角色/模板 key 保留小写 slug 约束。
- Prompt Pack 模板 tags 是否全部登记在 `配置/tag_taxonomy.json`，没有使用未登记同义词或 alias。
- Prompt Pack 模板 `api_profile` 是否进入 Markdown、JSON bundle、API 请求 JSONL/schema 和 CSV 索引，避免提示词和 API 参数分离后漂移。
- 自动导出提示词是否和 `配置/prompt_packs.json` 保持一致。
- 自动导出的 CSV 索引是否和 `配置/prompt_packs.json` 保持一致。
- 自动导出的 API 请求 JSONL/schema 是否和 `配置/prompt_packs.json` 保持一致，并能逐行解析为包含 `model`、`prompt`、`size` 和输出参数的 request。
- 自动导出的标签索引是否和 `配置/prompt_packs.json` 保持一致。
- 自动导出的标签覆盖矩阵是否和 `配置/prompt_packs.json` 与 `配置/tag_taxonomy.json` 保持一致。
- 覆盖矩阵是否过期，是否能反映当前角色与输出类型覆盖情况。
- GitHub Actions 是否调用统一质量门禁入口。
- 统一质量门禁是否编译 `工具/` 和 `tests/` 下的 Python 源码，避免未被测试导入的脚本藏语法错误。

## GitHub Actions

已添加 `.github/workflows/validate.yml`。
每次 push 或 pull request 都会运行质量门禁、Python 源码编译和单元测试：

```bash
python 工具/run_quality_gate.py
```

如果脚本报错，说明本次改动可能有断链、缺文件或安全约束遗漏，应该先修再合并。

## 新增内容前的人工检查

新增角色：

- 是否有发型、发色、头饰、服装、道具、气质。
- 是否有专属防串词。
- 是否明确非低俗、不性感化。

新增模板：

- 是否能放进已有分类，避免乱建文件。
- 是否用自然语言分段，而不是堆关键词。
- 如果包含文字生成，是否写了“短标题、清晰可读、不要乱码”。
- 如果是多格图，是否写了“同一角色一致性”。

新增预览图：

- 是否适合公开 README 展示。
- 是否压缩过。
- 是否没有水印、乱码、真实商标或低俗暗示。
- 是否在 `manifest.json` 中登记真实 `width`、`height`、`aspect_ratio` 和 `orientation`。
- 是否运行过 `python 工具/sync_preview_manifest.py`。

## Prompt Pack 导出检查

如果修改了：

```text
配置/prompt_packs.json
工具/build_prompt_pack.py
评估/failure_fix_lexicon.json
工具/validate_failure_fix_lexicon.py
```

需要重新运行：

```powershell
python 工具/run_quality_gate.py --refresh-generated
```

`check_prompt_repo.py` 会对比 `生成提示词/` 下的 Markdown 是否与当前配置生成结果完全一致。
`audit_character_prompts.py --check` 会对比 `评估/角色防串审计报告.md` 是否与当前配置生成结果完全一致。
`lint_prompt_quality.py --check` 会对比 `评估/Prompt文本质量审计报告.md` 是否与当前配置和质量规则完全一致。
`validate_failure_fix_lexicon.py --check` 会校验结构化失败修正词库的未知字段、非空白文本、适用角色、重复列表项和核心修正词，并对比 `评估/失败修正词库.md` 是否与 JSON 同步。
`validate_output_evaluations.py --check` 会校验结构化出图评分示例中的 slug ID、未知字段、真实日期、分数、Prompt Pack/角色引用、图片路径、图片文件后缀、version / description / issues / next_action / notes 非空白文本和 failure_ids，并阻止重复失败类型放大统计。
`summarize_output_evaluations.py --check` 会对比 `评估/出图评分汇总.md` 是否与结构化评分记录同步。
`suggest_failure_fixes.py --check` 会对比 `评估/失败修正建议.md` 是否与结构化评分记录和失败修正词库同步，并确保 `keep` 记录不会被误列为待修建议。
`validate_api_requests.py --check` 会对比 `生成提示词/prompt_packs.api_requests.jsonl` 和 schema 是否与当前 Prompt Pack 配置同步。

## 单元测试覆盖

`tests/test_prompt_pack_tools.py` 当前覆盖：

- Prompt Pack 配置校验。
- 所有 pack 渲染后的必要字段。
- Markdown 输出标题和代码块。
- `--all` 批量导出结果。
- CLI 的 `--validate` / `--list`。
- 总质量门禁脚本是否通过。
- 角色防串审计报告是否最新。
- Prompt 文本质量审计报告是否最新。
- 失败修正词库是否有效并同步生成 Markdown。
- 结构化出图评分示例是否有效。
- 出图评分汇总是否最新。
- 失败修正建议是否最新。
